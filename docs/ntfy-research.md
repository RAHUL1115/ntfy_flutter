# Minimum viable ntfy Flutter/Android client

_Research snapshot: official [ntfy server `4c2b69e`](https://github.com/binwiederhier/ntfy/tree/4c2b69e0591b51d7ed7b2e71954f0f7be936b47f), upstream Android clone at [`51730a0`](https://github.com/binwiederhier/ntfy-android/tree/51730a0f06cebfad59f1b7bc0cb6d5c47082b032), and comparison Flutter clone at [`e4f1ba7`](https://github.com/Virtuozs/ntfyd/tree/e4f1ba7257a0617f52b018caba2814c22415621b). “Local” paths below are relative to those clones._

## Recommendation: the smallest useful MVP

Build an Android-first, receive-and-publish client with only these flows:

1. Request notification permission; add a subscription using **server base URL + topic + optional Basic/Bearer credentials**. Topics on public `ntfy.sh` are effectively shared secrets, so the UI should encourage an unguessable name. ([ntfy publish docs](https://docs.ntfy.sh/publish/#picking-a-topic), [Android permission docs](https://developer.android.com/develop/ui/views/notifications/notification-permission))
2. Show saved topics, unread count/latest message, and a topic detail feed. On add/reconnect, fetch cached messages; then maintain a live WebSocket while the foreground service is enabled. ntfy supports catch-up by message ID and combining topics in one connection. ([subscribe API](https://docs.ntfy.sh/subscribe/api/#fetch-cached-messages), [multiple topics](https://docs.ntfy.sh/subscribe/api/#subscribe-to-multiple-topics))
3. Persist each subscription, messages, and its last event ID; deduplicate by `(server, topic, id)`. Display a local Android notification for a new `message`, and open its topic when tapped. This mirrors upstream's persisted `Subscription`/`Notification` split and dispatcher. ([local `app/src/main/java/io/heckel/ntfy/db/Database.kt`](https://github.com/binwiederhier/ntfy-android/blob/51730a0f06cebfad59f1b7bc0cb6d5c47082b032/app/src/main/java/io/heckel/ntfy/db/Database.kt), [NotificationService.kt](https://github.com/binwiederhier/ntfy-android/blob/51730a0f06cebfad59f1b7bc0cb6d5c47082b032/app/src/main/java/io/heckel/ntfy/msg/NotificationService.kt))
4. Support plain-text publish to an existing topic, with optional title/priority/tags; allow unsubscribe. PUT or POST to `/{topic}` is sufficient. ([publish docs](https://docs.ntfy.sh/publish/), [local `ApiService.kt`](https://github.com/binwiederhier/ntfy-android/blob/51730a0f06cebfad59f1b7bc0cb6d5c47082b032/app/src/main/java/io/heckel/ntfy/msg/ApiService.kt))

Defer attachments, actions, Markdown, scheduled delivery, updates/clear/delete UI, sharing/deep links, groups, pinning, quiet hours, per-topic channels, custom certificates/headers, UnifiedPush distributor support, backup, biometrics, themes, and multi-account management. They are useful upstream features, but none is needed to prove reliable subscribe → notify → inspect → reply. ([phone-client overview](https://docs.ntfy.sh/subscribe/phone/), [publish parameter list](https://docs.ntfy.sh/publish/#list-of-all-parameters))

## HTTP/API and model

- **Subscribe:** `GET {base}/{topic[,topic2]}/json?since={id|all|none}` returns newline-delimited JSON and stays open; `.../ws?since=...` returns equivalent JSON objects over WebSocket. `poll=1` drains available messages and closes. Use `since=all` only for first import, then the last processed ID. ([JSON stream/WebSocket/poll docs](https://docs.ntfy.sh/subscribe/api/), [local URL builders](https://github.com/binwiederhier/ntfy-android/blob/51730a0f06cebfad59f1b7bc0cb6d5c47082b032/app/src/main/java/io/heckel/ntfy/util/Util.kt))
- **Publish:** PUT/POST UTF-8 text to `{base}/{topic}`. MVP metadata may be `X-Title`, `X-Priority` (1–5; 3 default), and `X-Tags`; JSON publish exists but must target the server root and is unnecessary for MVP. ([publishing](https://docs.ntfy.sh/publish/), [JSON publishing](https://docs.ntfy.sh/publish/#publish-as-json))
- **Events:** required envelope fields are `id`, Unix-seconds `time`, `event`, and `topic`. Handle `message`; ignore `open`/`keepalive`; recognize `message_delete` and `message_clear` so later sequence support is forward-compatible. Message fields include `sequence_id`, `message`, `title`, `tags`, `priority`, `click`, `actions`, and `attachment`. ([official JSON model](https://docs.ntfy.sh/subscribe/api/#json-message-format), [local `Message.kt`](https://github.com/binwiederhier/ntfy-android/blob/51730a0f06cebfad59f1b7bc0cb6d5c47082b032/app/src/main/java/io/heckel/ntfy/msg/Message.kt))

Normalize a base URL to `http(s)://host[:port]` without a trailing slash/path, and validate topics with server-compatible `[-_A-Za-z0-9]{1,64}`. Keep credentials per base URL and send `Authorization: Basic …` or `Bearer …` headers over HTTPS; do not put credentials in the `auth` query parameter. ([server regex source](https://github.com/binwiederhier/ntfy/blob/4c2b69e0591b51d7ed7b2e71954f0f7be936b47f/server/server.go), [auth docs](https://docs.ntfy.sh/publish/#authentication), [local validation/auth](https://github.com/binwiederhier/ntfy-android/blob/51730a0f06cebfad59f1b7bc0cb6d5c47082b032/app/src/main/java/io/heckel/ntfy/util/HttpUtil.kt))

## Android background delivery

Android 12+ generally forbids starting a foreground service while already backgrounded, and Android 13+ gates normal notifications behind runtime `POST_NOTIFICATIONS`; therefore start delivery from a user-visible onboarding action and show the required ongoing service notification. ([background-start restrictions](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start), [notification permission](https://developer.android.com/develop/ui/views/notifications/notification-permission))

Upstream's Play flavor subscribes to FCM topics only for its configured main host (`ntfy.sh`); its FCM service handles data events and can schedule a one-off poll. Self-hosted/F-Droid/“instant” subscriptions instead run a sticky foreground service, group topics into one WebSocket/JSON connection per base URL, reconnect, and use an hourly WorkManager poll as catch-up. ([local `FirebaseService.kt`](https://github.com/binwiederhier/ntfy-android/blob/51730a0f06cebfad59f1b7bc0cb6d5c47082b032/app/src/play/java/io/heckel/ntfy/firebase/FirebaseService.kt), [`SubscriberService.kt`](https://github.com/binwiederhier/ntfy-android/blob/51730a0f06cebfad59f1b7bc0cb6d5c47082b032/app/src/main/java/io/heckel/ntfy/service/SubscriberService.kt), [`MainActivity.kt`](https://github.com/binwiederhier/ntfy-android/blob/51730a0f06cebfad59f1b7bc0cb6d5c47082b032/app/src/main/java/io/heckel/ntfy/ui/MainActivity.kt), [official instant-delivery explanation](https://docs.ntfy.sh/subscribe/phone/#instant-delivery))

FCM is **not an MVP shortcut**: a different app needs Firebase client configuration matched to a server configured with that Firebase project's service key. Add it later only if that infrastructure exists. UnifiedPush is also later: upstream ntfy acts as a distributor for other apps; it is not the transport replacing this client's own foreground connection. ([FCM server setup](https://docs.ntfy.sh/config/#firebase-fcm), [UnifiedPush docs](https://docs.ntfy.sh/subscribe/phone/#unifiedpush))

Use foreground service type `specialUse` with a manifest explanation, as upstream does, subject to Play review. Do not copy ntfyd's `dataSync` type unchanged: target-35+ apps get only six background hours per 24 hours and cannot launch that type from `BOOT_COMPLETED`. WorkManager periodic work is inexact and has a 15-minute minimum, so it is recovery—not instant delivery. ([service types](https://developer.android.com/develop/background-work/services/fgs/service-types#special-use), [timeouts](https://developer.android.com/develop/background-work/services/fgs/timeout), [periodic work](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work#schedule_periodic_work), [local upstream manifest](https://github.com/binwiederhier/ntfy-android/blob/51730a0f06cebfad59f1b7bc0cb6d5c47082b032/app/src/main/AndroidManifest.xml))

## Flutter shape and ntfyd comparison

MVP dependencies: [`http`](https://pub.dev/packages/http), [`web_socket_channel`](https://pub.dev/packages/web_socket_channel), [`sqflite`](https://pub.dev/packages/sqflite) (simpler than generated Drift for two/three tables), [`flutter_secure_storage`](https://pub.dev/packages/flutter_secure_storage), [`flutter_local_notifications`](https://pub.dev/packages/flutter_local_notifications), and either [`flutter_foreground_task`](https://pub.dev/packages/flutter_foreground_task) configured as `specialUse` or a small native Kotlin service bridged with [platform channels](https://docs.flutter.dev/platform-integration/platform-channels). Flutter SDK state/streams are enough; add WorkManager only after instant delivery works.

ntfyd is a useful design catalogue: its core/network, feed poll/WS, secure credentials, subscription, notifications, database, and basic publish modules map to MVP concerns. However, it opens one WebSocket per topic, declares `dataSync`, and its foreground task handler is a no-op while connections remain in the app isolate. ([local `lib/features/feed/data/repositories/feed_repository_impl.dart`](https://github.com/Virtuozs/ntfyd/blob/e4f1ba7257a0617f52b018caba2814c22415621b/lib/features/feed/data/repositories/feed_repository_impl.dart), [`foreground_service_controller.dart`](https://github.com/Virtuozs/ntfyd/blob/e4f1ba7257a0617f52b018caba2814c22415621b/lib/features/notifications/data/foreground_service_controller.dart), [local manifest](https://github.com/Virtuozs/ntfyd/blob/e4f1ba7257a0617f52b018caba2814c22415621b/android/app/src/main/AndroidManifest.xml))

Remove/avoid ntfyd's `groups`, app lock, broad settings/themes, advanced publish/attachments, account/health screens, Bloc/Cubit, Freezed/code generation, `get_it`/`injectable`, `rxdart`, `local_auth`, `dynamic_color`, Markdown, file picker, and unused Firebase/connectivity/logger dependencies. Its README claims Firebase delivery, but committed Dart code has no Firebase initialization/handler; its sequence-event handling also clears a whole topic or deletes by event ID instead of applying `sequence_id`. ([feature tree](https://github.com/Virtuozs/ntfyd/tree/e4f1ba7257a0617f52b018caba2814c22415621b/lib), [`pubspec.yaml`](https://github.com/Virtuozs/ntfyd/blob/e4f1ba7257a0617f52b018caba2814c22415621b/pubspec.yaml), [event handling](https://github.com/Virtuozs/ntfyd/blob/e4f1ba7257a0617f52b018caba2814c22415621b/lib/features/feed/data/repositories/feed_repository_impl.dart))
